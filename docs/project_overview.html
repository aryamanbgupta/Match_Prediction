4. End-to-end flow

Five steps from raw Cricsheet to a sliced eval report. Each step is independently cacheable.

Cricsheet refresh — fetch_cricsheet.py
Idempotent. SHA-256 manifest, append-only JSON merge across 14 leagues + the player register.
Build stats cache — build_stats_cache.py · ~6 min
Chronological walk; trackers updated ball-by-ball. First-write-wins snapshot per date. Global prior π computed over 2.19 M training balls and stored in _meta.prior_p*.
Materialize features — materialize_features.py · ~3 min
Per-date batches: rehydrate temp_* trackers from SQLite, replay same-day matches in monolith order, write 4 parquet splits.
Train — xgboost_v2.py · ~5–10 min
Load splits, fit LabelEncoders, 6-class remap, optional Optuna 50-trial tune, save to models/xgb_v3/.
Evaluate — sim_eval/run_sim_eval.py · 16.6 min (4-proc) / 41.9 min (serial)
261 matches × 100 sims. log loss + Brier + signed edge + 3 betting strategies + bootstrap 95 % CIs. --min-volume slices for 50 K / 100 K liquidity.

Empirical-Bayes shrinkage (the v6 / v7 trick)

p̂_c = (n_c + k · π_c) / (N + k)        where N = Σ n_c

   π = corpus prior, computed during cache build over 2.19 M balls
   π = (0.304, 0.411, 0.076, 0.108, 0.047, 0.054)
        dot    one    two   four   six    W

   k = 30  for player cells     N → 0  ⇒ p̂ → π   (full prior fallback)
   k = 200 for venue cells      N → ∞  ⇒ p̂ → MLE (data dominates)
                                N = k  ⇒ half-and-half

v7 hierarchical (the four narrow cells only):
   p̂_overall  = shrink(n_overall, π,         k=30)
   p̂_vs_pace  = shrink(n_vs_pace, p̂_overall, k=30)

7. How we evaluate

Three slices, three betting strategies, one explicit go / no-go gate.

Per-match procedure

for each match in 261 polymarket matches:
    state         = TestMatchLoader.from_json(match)
    market_probs  = BettingOddsLoader.implied_probs(odds, normalize=False)  # margin-free
    sim_results   = SimulationEngine.simulate_multiple(state, n_sims=100)
    sim_probs     = aggregate(sim_results)

    log_loss      = −log P(actual_winner)
    brier         = (P(team1) − 1{team1_won})²
    edge[t]       = sim_probs[t] − market_probs[t]
    signed_edge   = +|edge|  if predicted_winner == actual_winner else −|edge|

    flat_pnl      = +1 unit if model > market, P&L from decimal odds
    full_kelly    = (b·p − q) / b · bankroll        # b = decimal_odds − 1
    frac_kelly    = ¼ · full_kelly                  # safer in practice

8. Critical invariants & design choices

The non-obvious decisions that drive correctness, performance, and reproducibility.

Temporal integrity

Features reflect state before the ball; trackers update after. Verified bit-exact on all 9 519 male T20 matches via test_phase_a_parity.py.

6-class outcome space

{0:dot, 1:one, 2:two, 3:four, 4:six, 5:wicket}. Wides + no-balls added post-hoc at 1 % each, then re-normalised.

Schema versioning

Any change to _SQLiteBackend tables bumps SCHEMA_VERSION. Provider refuses to open a file with the wrong version. Currently 4.

Same-day match order

Within a single date, matches are processed in monolith order. temp_* trackers carry state across same-day siblings; reordering changes features for every match.

--parallel is a trap

Intra-match --parallel is correct but slower than serial — IPC pickle overwhelms the gain. Use perf_runs/run_n_parallel.py (4 procs at OMP=2 → 2.52× full eval).

Calibration ≠ resolution

Coinflip (LL 0.6931) beats v7 on ≥$50K (LL 0.7402) — under-resolution, not miscalibration. Calibration alone can't close it; new feature signal must.
