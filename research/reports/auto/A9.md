# A9 — E4 quantile pooling forward test

**Status: FAILED** (2026-07-11) · commit `abb6823`

## Hypothesis
E4 (`reports/e4_quantile_pooling.md`) added 8 quantile-pooled ELO "survivor"
features on top of the M2-venue-only base (best-2 bowling ELO per team, bowling
ELO maxima, and the batting-ELO-spread / best-2-bowling diffs). E4 **discarded**
them on its pre-registered val rule (val LL got *worse*: +0.0045), but on the
iteration readout the +8 variant (**all8**) was directionally better on every
slice and E4 filed it as a forward-test candidate:
*"re-test all8 on forward-captured data when ≥50 fresh matches exist."*
A9 forward-tests it under this loop's dual-metric ≥$50k gate.

## The 8 survivor features
`team2_top6_bat_elo_max`, `team1_bowl_elo_max`, `team1_bowl_elo_top2`,
`team2_bowl_elo_max`, `team2_bowl_elo_top2`, `top6_bat_elo_spread_diff`,
`bowl_elo_max_diff`, `bowl_elo_top2_diff`.

## Method (paired, seed-controlled)
- Built `data/auto/a9/` from the existing E4 unfrozen parquet
  (`data/xgb_match_data_v3_e4_unfrozen`), subset to
  `[metadata + the 54 non-encoded all8 features IN E4's EXACT column order]`.
  Column order is load-bearing: `colsample_bytree=0.9` samples columns by
  position, so a different order yields a different model at the same seed. With
  the E4 order restored, **seed 29 byte-reproduces E4**: base 0.6312/+15.38,
  all8 0.6288/+24.35 (verified against E4's on-disk models too).
- Trained BOTH `base` (48 feats; drop the 8 survivors) and `all8` (56 feats) on
  the SAME a9 parquet at A1's 5 seeds {29,7,13,42,101}, trainer defaults (matches
  recipe A). This is the only clean control: the E4-unfrozen base is *not* A1's
  `v2_clean` base (v2_clean is M1/frozen, 45 feats; e4-base is M2-venue-only/
  unfrozen, 48 feats), so a same-parquet base at the same seeds isolates the
  pure 8-feature effect.
- Recipe A eval each: `blend --w 0.0` → `reslice` vs `betting_odds_polymarket.json`
  → ≥$50k slice (170 matches, 168 bets, market LL 0.6267).

## Verdict: FAILED
- **LL**: paired mean ΔLL **+0.0019** — all8 is *worse* (higher LL), and sub-floor.
  Only seed 29 favors all8; the other 4 seeds are flat-to-worse. → not improved.
- **ROI**: paired mean ΔROI **−0.76pp** — all8 is *worse*, sub-floor; 3 of 5
  seeds worse. → not improved.

Neither gate metric improved (both moved slightly the *wrong* way, both inside
the noise floor) → **FAILED**.

**E4's promising single-seed readout was seed-29 luck.** Seed 29 is the sole seed
where all8 beats base on both LL and ROI, and it does so by a lot (ΔROI +8.97pp) —
which is exactly the readout E4 recorded and flagged. Across the 5-seed
distribution that signal vanishes: the quantile features are net-neutral-to-
slightly-negative on the winner market. This vindicates both (a) E4's own val
rule, which said DISCARD, and (b) this loop's requirement (A1/E3) to test
retrain ideas across ≥5 seeds rather than trust a single-seed iteration readout.

The E4 open hypothesis ("re-test all8 on forward-captured data") is hereby
**resolved negative** for the winner market. Note this is a same-set (iteration)
5-seed test, not brand-new forward matches; but the iteration "win" E4 saw is now
shown to be a seed artifact, so no forward capture is needed to close it.

No production code was changed (the quantile columns already live in the
materializer, excluded from production since E4; A9 only trained gitignored
scratch models under `models/auto/a9/`). The reproduction harness
`scripts/auto/a9_run.py` is kept (analogous to `a8_gate_analysis.py`).
