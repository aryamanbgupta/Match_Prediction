## Hypothesis

M8 documented (`reports/m8_sizing_rules_eval.md`, "Slice-conditional finding")
but never forward-tested as a rule: on lopsided matches the M7 production model
is over-confident at small edges, so requiring a larger edge there should
remove net-losing bets. A7 pre-registers the rule:

- **close** fixtures (`|top6_batting_elo_diff| ≤ 5`): bet flat, edge threshold 0.
- **mismatch** fixtures (`|top6_batting_elo_diff| > 5`): bet only when the
  model's edge on its preferred team **> 10%**.

The boundary (5) and mismatch edge threshold (10%) were fixed a priori from the
M8 write-up — not swept to find a winner (a 0.05/0.10/0.15 sweep is reported
below only for context; all three improve ROI).

## Method

Pure betting-layer filter on the **frozen production predictions** — no
retraining, no probability changes. `scripts/auto/a7_conditional_threshold.py`
reuses the eval framework's own helpers (read-only import) so the methodology is
identical to production:

- per-bet pnl = the framework's `realized_pnl` field (flat 1-unit, threshold-0
  production betting decision) from the resliced ≥$50k eval JSON
  (`eval_out_m7prod_sliced/..._min_volume_50000.json`, the M8/production output;
  its summary reproduces the CLAUDE.md headline exactly: LL 0.6299, ROI +21.90%,
  168 bets).
- slice membership = `top6_batting_elo_diff` via `_load_feature_lookup` on the
  **unfrozen** parquet `data/xgb_match_data_v3_m6_unfrozen/test.parquet` (chosen
  because it reproduces M8's close-slice number exactly: n=76, +29.76%
  [+3.99, +58.36]; the frozen `v2_clean` parquet gives n=60 / −0.18% and is the
  wrong ELO source for the production predictions).
- CI = framework `_bootstrap_ci` (seed 42, n=1000).

The 2 matches missing from the parquet both have `realized_pnl=None` (no bet) —
all 168 bet matches have feature rows, so the join is complete.

### Mechanism (≥$50k, threshold-0 pnls decomposed)

| Subset | n | ROI | Action |
|---|---|---|---|
| close (≤5) | 74 | +33.27% | keep |
| mismatch kept (edge>10%) | 35 | +44.66% | keep |
| **mismatch dropped (edge≤10%)** | **59** | **−5.86%** | **remove** |
| all mismatch (>5) | 94 | +12.95% | — |

The rule removes a **coherent, economically net-losing** subset (−5.86% ROI over
59 bets), not a noise slice — so total profit rises even as bet count falls. This
independently reproduces M8's over-confidence-on-lopsided-matches finding.

## Verdict

Betting-layer idea → LL cannot move (predictions untouched). On the ≥$50k gate
ROI improves +15.03pp (>> 2pp eval-only floor) and **nothing degrades** — win
rate, drawdown, total profit, and CI lower bound all improve. **LANDED.** M8
declined to land this citing complexity + small-n; A7's mandate was exactly to
forward-test it as a rule, and it clears the betting-layer gate. Keep the commit
(scorer + report + results row). No model artifacts changed; the recommended
**production sizing rule becomes slice-conditional**: flat threshold 0 on close
fixtures, edge>10% on `|top6_batting_elo_diff|>5` mismatch fixtures. Wiring this
into a live betting harness (compute slice membership at inference, apply the
threshold) is the human-side follow-up — `predict_fixture.py` only emits
probabilities today, so no production code path changes here.
