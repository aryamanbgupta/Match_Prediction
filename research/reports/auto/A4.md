# A4 — Regularized logistic stack

**Verdict: TABLED** (2026-07-11). Standalone logistic FAILS; the 50/50
logit-average with M7 moves ROI (+3.06pp vs fresh baseline, clears the 2.3pp
floor) but NOT LL (−0.0020, inside the 0.007 floor). Exactly one gate metric
improves → TABLED. Code reverted; idea kept as raw material for a future
combination.

## Hypothesis

A heavily L2-regularized logistic regression on the same signed-diff features
is a *different bias class* from XGBoost. Even if it loses standalone, it may
ensemble well — a linear model's errors are decorrelated from a tree's, so a
blend can beat both parents on a threshold metric like ROI.

## What I did

- New trainer `scripts/train_match_logistic_a4.py`: StandardScaler (train-fit)
  + `sklearn.LogisticRegression(penalty="l2")` on the **43 signed-diff numeric
  features** from `data/xgb_match_data_v2_clean`. The two label-encoded
  categoricals (`venue_id_encoded`, `competition_tier_encoded`) are **excluded**
  — they are arbitrary integer codes and a linear model reads them as a
  meaningless monotone ordering (invalid linear terms).
- Regularization strength **C selected on the validation split** (lowest val
  log loss; no test peeking). Grid swept down to C=3e-5; genuine interior
  optimum at **C=0.003** (val LL 0.6581; 0.001→0.003→0.01 forms a U).
- Emitted eval-compatible `test_predictions.json` and a **50/50 logit-space
  average** with the M7 production predictions.
- Recipe A: `blend_eval_json.py --w 0.0` → `reslice_eval_json.py` → read the
  ≥$50k slice for both the standalone logistic preds and the 50/50 blend.

## Verdict reasoning

- **Standalone**: LL worse by 0.0072 (beyond floor), ROI flat (+0.87pp <
  floor). Neither improves — fails as a standalone winner-market model, exactly
  as the hypothesis anticipated (a linear model underfits the tree's
  interactions; standalone LL 0.6390 > baseline).
- **50/50 blend**: exactly one gate metric clears its floor (ROI +3.06pp; LL
  −0.0020 does not) → **TABLED** per the dual-metric rule and per A4's own
  instruction ("if standalone fails but blend helps, TABLE with that note").

**Honest confound to carry forward:** the blend contains M7 production, a
specific *lucky* seed (its standalone ≥$50k LL 0.6299 beats the fresh-seed mean
0.6318; A1 noted seed luck of ~±0.007). Measured against **M7 alone** rather
than the fresh-seed mean, the logistic adds only +1.72pp ROI (inside the 2.3pp
floor) and −0.0001 LL — i.e. essentially nothing beyond noise. So part of the
+3.06pp "win" vs the fresh baseline mean is M7 seed luck being reintroduced,
not pure logistic signal. The genuinely notable fact is narrower but real: the
blend ROI exceeds both parents, so the linear member is *not useless* for
threshold-metric ensembling — just not enough to move LL.

## What I'd try next

The logistic is a weak-but-decorrelated ROI ensemble member that can't move LL
alone. The natural combination (a future C-series entry): fold the logistic
into a **multi-member ensemble that also removes seed variance** — e.g. a 3-way
logit-average of {logistic, A1 seed-bag mean, M7} — so the ROI decorrelation
survives while the seed-luck confound is averaged out and the LL floor is
approached from the tree side. Standalone logistic is dead; its only value is
as a blend member, and only if the blend's LL can be pulled below the fresh
mean by more than the 0.007 floor (this run did not). Keep `models/auto/a4/`
JSONs on disk for that combination.
