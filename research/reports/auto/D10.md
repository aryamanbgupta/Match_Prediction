### Known bugs documented as xfail (assert CORRECT behavior, expected to fail)

1. `test_xfail_aggregate_counts_zero_pnl_win_as_bet` —
   `match_evaluator.py:933,977` use `realized_pnl != 0` as the "bet was
   placed" test, so a placed bet that wins at decimal odds 1.0 (pnl exactly
   0.0) vanishes from bets_placed / win rate / Sharpe / the ROI denominator.
2. `test_xfail_reslice_counts_zero_pnl_win_as_bet` — same conflation at
   `reslice_eval_json.py:200-201`.

Both are the already-tracked **I3** interactive-backlog item (the fix
touches loop-forbidden files). The xfails are strict: if the bug is fixed
interactively, they flip to a loud XPASS error telling the fixer to remove
the marker. Practical severity today is low — polymarket odds are 1/p with
top_p ≤ 0.9995, so decimal odds 1.0 exactly cannot occur in the current
data — but the sentinel is a semantic landmine for any future odds source.

Also documented in a test comment (divergence, not a gate bug): the reslice
copy of `_bootstrap_ci` lacks the evaluator's `n_resamples <= 0` guard
(unreachable at the defaults every caller uses).
