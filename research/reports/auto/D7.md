# D7 — Team-swap symmetry augmentation (match model)

**Status: LANDED** (2026-07-17)
**Commits:** claim `9f04f66`, implement `9a3eb17` (kept)
**Artifacts:** `models/auto/d7/{base,swap}_seed{29,7,13,42,101}/` (gitignored),

## Hypothesis

The match model consumes absolute `team1_*`/`team2_*` features and team
assignment is arbitrary cricsheet order, so it is not antisymmetric — and it
shows (train/val/test base rates 0.488/0.476/0.472; asymmetric importances).
Augmenting each train row with its team-swapped copy (exchange team columns,
negate signed diffs, flip label) doubles effective n to ~15.8k and enforces
P(t1|A,B) = 1 − P(t1|B,A). Training-procedure change, no new features — the
M3–M6 correlation-check discipline doesn't apply.

## What was done

- `scripts/xgboost_match_v1.py` gains `--swap-augment` (opt-in, default off —
  recipe-A baseline semantics unchanged): TRAIN-only mirrored copy of every
  row. Mapping over the v2_clean schema: **13 pairs** exchanged
  (elo/avg/sr/econ/win-rate/lineup-mix/home/top6/bottom5 + team names),
  **7 signed diffs** negated, **4 flips** 1−x (`h2h_team1_win_rate_shrunk`,
  `toss_winner_is_team1`, `team1_batting_first`, label `team1_wins`),
  **12 invariants** (venue character, `is_international`,
  `toss_decision_bat`, `h2h_n_meetings`, ids/dates). Val/test never
  augmented (val stays raw for early stopping).
- Hard-fail guards: unclassified column → ValueError; swap(swap(df)) == df
  involution asserted at run time.
- Pre-run verification (all exact): 7/7 diff identities max|diff−(t1−t2)| =
  0.0 on the train parquet; h2h Beta(1,1) prior exactly 0.5 on all 1,728
  n=0 rows (so 1−x is the exact mirror); no-result/tie matches are dropped
  at materialization so the label flip is always valid; augmented train
  7,912 → 15,824 rows at base rate exactly 0.500000.
- Paired 5-seed run (A1 seeds {29,7,13,42,101}), base vs swap on
  `data/xgb_match_data_v2_clean`, trainer defaults (M7 config), recipe A
  per seed. **Same-session base reproduces A1's logged numbers EXACTLY on
  all 5 seeds** (no env drift; the paired control is clean).

Secondary observations:

- **Swap mean LL 0.6196 beats the market reference 0.6267** on the iteration
  ≥$50k slice — every individual swap seed does (max 0.6244). First
  retrain-based idea in this loop to put model LL below market LL.
- **Seed variance collapses**: LL seed std 0.0068 → **0.0027** (ROI std flat,
  2.29 → 2.56pp). The symmetry constraint removes most of the seed luck A1
  quantified — future retrain gates on a swap-augmented baseline would need
  a re-measured floor.
- **ROI CI lower bound > 0 on 5/5 swap seeds** (base: 2/5). Single-seed ROI
  claims stop being fragile under augmentation.
- ≥$100k context (110 bets): ΔLL −0.0233 (0.5914 → 0.5681 mean), ROI +26.14
  → +30.02%, CI lo > 0 on 4/5 swap seeds (base 1/5).

## Verdict

**LANDED.** `--swap-augment` stays in the trainer (opt-in; default path and
the A1 fresh-baseline semantics unchanged). Production adoption (retraining
`xgb_match_v3_m7_production` with augmentation on its unfrozen 48-feature
parquet) is deliberately NOT done here — that config lives on a different
parquet and is a human/follow-up decision (see D12).

## What I'd try next

Two follow-ups appended to the queue: **D11** — inference-time
symmetrization (average p(A,B) and 1 − p(B,A) at predict time; the trained
model is still not exactly antisymmetric, and averaging the two orientations
is a free eval-only variance cut on top of D7 — flagged by D7's own gate
note). **D12** — transfer confirmation on the production config: extend the
swap mapping to the M2 outcome-dist columns (3 venue_p* invariants + 12
expected-pair columns + 6 diffs already classified by the hard-fail guard),
subset `data/xgb_match_data_v3_m3_unfrozen` to the production 48-feature
list (A9 pattern), paired 5-seed. If it transfers, the production-adoption
case is complete. Also worth noting: the collapsed seed std (0.0027) means
a future swap-augmented baseline row would let ideas clear the LL floor at
~2.5× finer resolution.
