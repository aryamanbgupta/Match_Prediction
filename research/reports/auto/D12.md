## Hypothesis

D7 landed team-swap symmetry augmentation on the loop's recipe-A baseline
(v2_clean frozen parquet, 45 features, no monotone constraints). Production
(`models/xgb_match_v3_m7_production`) differs in three ways: unfrozen
tracker semantics, the M2-venue-only 48-feature set (adds venue_p4/p6/pw +
venue/tier encodings), and monotone constraints ON. If the augmentation gain
transfers to that configuration, the production-adoption case is complete
(adoption itself stays a human decision).

## What was done

1. **Swap-mapping extension** (`scripts/xgboost_match_v1.py`): `_SWAP_PAIRS`
   += the 6 M2 expected pairs, `_SWAP_NEGATE` += the 6 M2 diffs (all verified
   exactly `t1 − t2` on the m3_unfrozen parquet, dev 0.0), `_SWAP_INVARIANT`
   += `venue_p4/p6/pw` (venue properties). Note: the production feature list
   carries **no M2 team-level columns** (M2 landed venue-only), so on the D12
   frame the new pair/negate entries are verified no-ops; only the 3 venue
   invariants are live. The hard-fail coverage guard forced the extension to
   be explicit and total, as intended.
2. **Production frame** (`scripts/auto/d12_build_parquet.py` →
   `data/auto/d12/`): no parquet with exactly the production schema survives
   on disk, so `data/xgb_match_data_v3_m3_unfrozen` (90-col superset, same
   7912/525/791 splits as production's `train_metrics.json`) was subset to
   metadata + the 46 production numeric features **in exact
   `feature_columns.txt` order** (colsample makes order load-bearing — A9
   lesson). `golden_test.parquet` deliberately not copied.
3. **Config verification**: production `model.pkl` inspected — monotone
   constraints ON (12 non-zero), lr 0.05, cs 0.9, seed 29, otherwise trainer
   defaults. Both D12 arms therefore run `--monotone` + defaults (D7 ran
   without monotone; this is a real config delta being tested).
4. **Paired 5-seed eval** (`scripts/auto/d12_run.py`, A1 seeds
   {29,7,13,42,101}): base vs `--swap-augment`, recipe A (blend w=0.0 →
   reslice ≥$50k / ≥$100k). Pre-run verification all green: feature order ==
   production (48 cols), 7 M1 diff identities exact 0.0, h2h prior 0.5 on
   1,728 n=0 rows, involution + coverage OK, augmented train 15,824 rows at
   base rate exactly 0.5.

the comparison is production-vs-production+swap with nothing else moving.

## Caveats / secondary findings

1. **M7's headline is confirmed seed-29 luck.** The 5-seed base mean on the
   *production config itself* is LL 0.6378 / ROI +19.67% vs the logged
   0.6299 / +21.90% — seed 29 is the best base seed on both metrics.
   Vindicates the E3 guidance to temper the production ROI expectation
   (~+16–20%, not +22%).
2. **D7's LL-std collapse does NOT transfer.** Swap LL seed-std here is
   0.0060 (base 0.0048); on v2_clean it collapsed 0.0068 → 0.0027. The ROI
   std halving does transfer. Any future gating against a swap-augmented
   baseline must re-measure the seed floor **per config** rather than assume
   D7's 0.0027.
3. **The loop frame outscores the production frame under swap** on the
   iteration set (v2_clean+swap mean 0.6196 vs production+swap 0.6286).
   Different tracker semantics (frozen vs unfrozen) and feature sets;
   production chose unfrozen on deployment-semantics + golden grounds, and
   the golden set is off-limits here — flagged for the interactive backlog,
   not relitigated by the loop.
