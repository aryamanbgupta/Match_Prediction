# D1 — Fix sim-side `run_rate` scale skew (runs-per-over vs runs-per-ball)

**Verdict: LANDED** (2026-07-17). Two-iteration relay: the earlier 2026-07-17
iteration claimed (`b5173e9`), implemented + pre-committed the gate

## Hypothesis

Training computes `run_rate` as runs-per-OVER
(`parsing_v2.calculate_basic_features`: `score / max(overs, 0.1)`), but the
sim wrappers computed runs-per-BALL (`score / (balls + 1)`) — a ~6.24×
scale skew on every simulated ball, the same OOD-input bug class as the
B1/B6 venue blindness. Mandated correctness fix from the 2026-07-16
supervisor review (D-series).

## What was done

- Aligned every sim-side `run_rate` assembly site in `scripts/sim_v1_2.py`
  to the training formula `score / max(balls/6, 0.1)`:
  - `XGBoostModelV2` (:761, the live v7 path — was runs-per-ball, the real bug)
  - legacy `XGBoostModel` (:1190, same bug)
  - LSTM / MLP / MLPv2 / Transformer blocks (per-over scale was already
    right; zero-guard aligned from `max(balls,1)*6` to `max(balls/6, 0.1)`)
  - `run_rate_required` chase features untouched (already correct).
- **Gate 1 (teacher-forced training parity), established pre-run:** the
  aligned formula reproduces the training parquet `run_rate` exactly —
  max|parquet − formula| = 0.0 across 310,959 test+validation rows; live
  `extract_features` spot check exact on 6 states including the
  balls=0/score>0 guard case.
- One recipe-B run: n=261 × 100 sims, **seed 43**, default venue-ON path
  (startup log: "venue encoder ACTIVE (467 venues)"), stale v1 vector
  calibrator — identical settings to the B6 canonical baseline, so the
  ONLY delta in the pair is the `run_rate` formula.
- Paired (d1 − base) Brier/MAE, cluster-bootstrapped by match, via
  pre-committed `scripts/auto/d1_gate_analysis.py` (committed in `8fd5a8a`
  before any sim result existed). Baseline:
  `models/auto/b6/detail_venue_s43_n261.json`.

## Reading

within-innings pace signal should matter: `highest_over_runs` (which over
explodes — the model previously saw a near-zero "run rate" all innings),

`top_batter`) — reproducing the B1/B6 pattern that per-ball input-integrity
fixes surface as batter-level sharpening while multi-over team aggregates
wash out (A8/A12/A16). `run_rate` ranks ~104/114 by gain, which capped the
effect size; the direction is uniformly favorable.
