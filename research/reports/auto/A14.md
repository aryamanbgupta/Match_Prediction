# A14 — Per-over (not per-3-phase) ball calibrator for single-over props

**Verdict: LANDED** (2026-07-11). Sim/prop gate pair — both conditions met.
Kept commit `0e1bbb0` (implement) + `cdf0d4a` (claim).

## Hypothesis

A8 (phase-conditional 3-bucket vector scaling) netted to **null** on
`team_first_over_mae` (dMAE +0.003, noise) because a bowler's/team's balls
span phases and the small per-ball corrections wash out on multi-phase
aggregates. But **single-over** props live inside one over — and A8's
powerplay bucket lumps **over 0 (the first over) with overs 1–5**, so the
distinctive new-ball / field-restriction behaviour of the first over is
averaged away. A calibrator indexed **per over** (0–19) has resolution A8's
flat buckets lacked *precisely where it can't wash out*.

## What I did

- **`calibration.py`**: added `OverVectorScalingCalibrator` (`over_aware=True`)
  + a shared `_fit_scaling_vector` helper. Twenty independent 6-vectors — one
  per over — each fit by the same iterative marginal-matching as E5's landed
  `VectorScalingCalibrator`, plus a global fallback vector. The global fallback
  **reproduces v1 exactly** (max abs diff 0.00e+00 — the fitting pipeline is
  validated by that identity). All 20 overs had ≥4235 val balls → 0 fallbacks.
  Over 0 diverges most from global (six ×1.23 / wicket ×1.23 up, four ×0.85
  down) — the first-over resolution A8's PP bucket averaged out.
- **`sim_v1_2.py`**: `XGBoostModelV2` reads `balls_bowled` off the feature
  buffer; `predict_next_ball` dispatches the over (`balls_bowled // 6`, clamped
  0–19) when the calibrator is `over_aware`. The default global-vector path
  (E5 `vector_scaling_calibrator_v1.pkl`) is **byte-for-byte unchanged** (the
  `else` branch is identical to prior) → production sim behaviour is preserved
  unless the over-calibrator is explicitly passed. Not an eval-framework file
  (same engine A8 edited).
- **`scripts/auto/a14_fit_over_calibrator.py`**: fits
  `models/auto/a14/over_vector_calibrator.pkl` (gitignored scratch;
  reproducible from this committed script).

## Eval — paired Brier/MAE (over − vec), n=261 × 100 sims, seed 42, cluster-boot by match

Baseline = A8's single-vector run `models/auto/a8/detail_vec_n261.json`
(v1 calibrator, seed 42, `EmpiricalBowlerSelector`, same test dir). Over-run =
`models/auto/a14/detail_over_n261.json`. Both score identical lineups/lines →
positional pairing valid; only the ball calibrator differs. Analysis:
`scripts/auto/a8_gate_analysis.py`.

## Verdict

Gate 1 improves (CI excludes 0) **AND** Gate 2 guard held (no regression) →
**both conditions of the sim pair met → LANDED.** The hypothesis is vindicated:
A8's 3-phase bucket was null on `team_first_over_mae` because over 0 was lumped
with overs 1–5; per-over resolution recovers the first-over correction with a
CI that excludes 0. Net cost is nil within noise on the bowler-wicket guards.

## What I'd try next

The entire win is concentrated in **over 0**, whose vector diverges most from
global (six/wicket ×1.23). A 20-vector calibrator is a lot of parameters to
carry for a one-over effect, and the other 19 per-over vectors buy nothing
observable. The cleanest follow-up (queued as **A15**) is a **minimal
over-0-only calibrator** — one first-over vector + the global vector for overs
1–19 (2 vectors, not 20). If it captures the full `team_first_over_mae` gain
with far fewer parameters, prefer it: same signal, less overfitting surface,
and it isolates *where* the first-over model error lives. Separately, the
first-over distribution is still under-dispersed (P10–P90 coverage 65% vs 80%),
so A13's dispersion lever remains orthogonal and complementary — a natural
C-series combination once PENDING runs dry.
