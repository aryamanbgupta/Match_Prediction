# A8 — Phase-conditional vector scaling (E5 follow-up)

**Verdict: FAILED** (2026-07-11). Null-effect refinement. Implementation
reverted (`f532396` reverts `51ed044`); scratch artifacts kept on disk under

## Hypothesis

E5 fixed the sim's tail-event overshoot with one global `VectorScalingCalibrator`
(`models/xgb_v3/vector_scaling_calibrator_v1.pkl`) that undoes the `balanced`
class-weight tilt in the booster's raw ball probabilities. The E5 report noted a
residual: the tilt is not uniform across match phases, so a single global
6-vector fixes *marginal* class rates yet under-corrects boundary-heavy contexts.
The hypothesis: fit **three** independent 6-vectors — powerplay / middle / death —
so per-phase scaling removes the residual bowler-wicket / PP-total overshoot
without breaking what E5 fixed.

## What I did

- `PhaseVectorScalingCalibrator` (calibration.py): 3 phase-bucket 6-vectors, each
  fit by the same iterative marginal-matching as E5's `VectorScalingCalibrator`,
  on the validation balls of one phase only (pp = balls<36, mid = 36≤balls<96,
  death ≥96 — matching `XGBoostModelV2.extract_features`). A global fallback vector
  reproduces v1 exactly (validated: **max abs diff vs v1 = 0.00e+00**).
- `sim_v1_2.py`: `XGBoostModelV2.predict_next_ball` reads the ball's phase off the
  feature buffer (`is_powerplay`/`is_death_overs`, both present in the 114-feature
  v3 set) and dispatches the right vector when the calibrator advertises
  `phase_aware=True`; the default global-vector path (E5) is byte-for-byte
  unchanged (`VectorScalingCalibrator` has no `phase_aware` attribute → old path).
- **No eval-framework edit.** `prop_backtest.py`'s existing `--ball-calibrator
  vector` just `joblib.load`s `--ball-calibrator-path`; pointing that at the phase
  calibrator pkl selects it. `scripts/sim_eval/` untouched.

The per-phase vectors do diverge from the global one (ratio phase/global):

## Verdict

Sim gate pair: metric 1 (tail overshoot) **not improved** (pooled dBrier −0.0001,

gate metric improved → FAILED.** Code reverted.

Note: an earlier n=30 smoke (pairing the leftover 30-match vec baseline against a
30-match phase run) showed all-worse with the pooled tail CI barely excluding 0

## Why it's null (and what I'd try next)

The global vector already matches the dominant *overall* marginal, and the
phase vectors diverge from it by only 3–7%. Prop-level tail families aggregate over
many balls spanning multiple phases (a bowler bowls across PP/mid/death;
`bowler_wkts` sums all his overs), so the small per-ball, per-phase re-distribution
washes out by the time it reaches the aggregate. The one place it points the right
way — `pp_total_ou_45_5/50_5` (−0.0025/−0.0019), a purely-PP family — is exactly
where a phase vector *should* help, but even there the gain is inside noise and
`pp_total_ou_55_5` flips sign. The residual E5 named is real but too small to
extract with a 6-parameter-per-phase linear scaler.

Next directions if the residual is worth revisiting: (1) the residual overshoot is
plausibly **per-over-within-phase** (esp. over 20 vs over 16 in the death block),
not per-3-phase — a smooth over-indexed scaler or a monotone spline on `balls_bowled`
would have more resolution than 3 flat buckets; (2) it may be a **dispersion**
problem (sim under-disperses PP totals: P10–P90 coverage 53% on `team_first_over`),
which vector scaling cannot fix at all — a variance/temperature calibration on the
sampled counts, or negative-binomial dispersion on the per-ball outcome, is the
right lever. Neither is a small tweak, and E2's standing result — no binary prop
beats a fair baseline — means the ceiling here is continuous score forecasts, so I'd
gate any such work on `batter_runs_mae` / `highest_individual_mae` first.
