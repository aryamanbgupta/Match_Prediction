# B3 — Continuous-forecast shrinkage blend (productize E2's finding)

**Status:** LANDED
**Date:** 2026-07-23 (UTC)
**Commits:** claim 08e0453, implement ce6be5d (harness + pre-committed gate)

## Hypothesis

E2's standing result: the sim's only validated prop skill is continuous
score forecasts. A val-fit convex blend `alpha*sim + (1-alpha)*fair_baseline`
per MAE family should beat both parents — the best score forecast the
system can produce — because the sim (lineup/ELO/state-aware, high
variance) and the E2 as-of baselines (career/venue shrunk means, low
variance) plausibly carry decorrelated errors.

## Method

- **No sim-engine change, no re-baseline.** `prop_fair_baselines.py`
  imported read-only; corpus cache reused (verified 7-tuple venue_inn
  schema incl. team_fours, coverage through 2026-04-16). Non-engine
  pick: D3 consumed the night's one-sim-engine-idea slot (B4/B9
  precedent).
- **Val fit:** the exact ball-model val split (545 matches,
  2024-12-31..2025-06-29, stems from the post-B2
  `data/xgb_data_v3/cricket_data_v3_validation.parquet`) copied to
  `data/auto/b3/val_matches/`; ONE `prop_backtest.py` run at the
  canonical D15 engine config (venue-ON default path, attribution unit,
  run_rate-aligned, stale v1 vector calibrator; `--n-sims 100 --seed 42
  --ball-calibrator vector`). 545/545 matches, 0 skips, 4642.1 s.
  Engine verified byte-identical to the D15 state pre-run (empty
  `git diff 2f2051c HEAD -- scripts/sim_v1_2.py`).
- **Alpha fit (VAL-ONLY):** grid 0..1 step 0.01 minimizing row-mean
  `|blend - actual|` per family; ties toward 0.5. Harness
  `scripts/auto/b3_shrinkage_blend.py` (gate pre-committed at ce6be5d
  before any val or test result existed).
- **Test eval:** frozen alphas applied to the EXISTING canonical D15
  detail (`models/auto/d15/detail_d15_s43_n261.json`, seed 43, n=261) —
  no new test run. Paired per-row |err| deltas, cluster bootstrap by
  match (2000 resamples, seed 29 — the E2/B4/B9 statistic).
- **Pre-run caveat (stated at implement time):** the v1 vector
  calibrator was E5-fit on these same val balls, so val sim forecasts
  carry a small in-sample optimism -> alpha may lean slightly toward
  sim vs the test optimum. Confirmed in direction — see context.

## Pre-committed gate

Families = the 5 MAE families with defined E2 fair baselines:
`batter_runs_mae`, `highest_individual_mae`, `team_total_fours_mae`,
`team_total_sixes_mae`, `team_first_over_mae` (`batter_fours_mae` has no
baseline). GATE 1 = blend beats BOTH parents CI-clean on >=1 family.
GATE 2 = no family CI-clean worse than its best (test point-estimate)
parent. Both -> LANDED; exactly one -> TABLED; none -> FAILED.

## Context (post-verdict diagnostics, not used for selection)

Val alpha -> test-optimal alpha: batter_runs 0.93 -> 0.78;
highest_individual 0.83 -> 0.68; team_fours 0.64 -> 0.35;
team_sixes 0.79 -> 0.59; first_over 0.15 -> 0.28. Every sim-heavy family
leans sim on val relative to test — the pre-run E5-calibrator-in-sample
caveat confirmed in direction. The land survives the lean: even with
sim-flattered alphas the blend never loses to the best parent.

## Reading

The blend is now the system's best continuous score forecast: never
worse than either parent anywhere, CI-clean better than both exactly
where the sim has real skill (per-batter runs, team sixes), and it
silently converts to ~the baseline where the sim is weak (first over,
alpha 0.15). This productizes E2's finding as one artifact
(`models/auto/b3/alpha.json` + `scripts/auto/b3_shrinkage_blend.py`) —
any live prop quote for a continuous family should read the blend, not
the raw sim. Production wiring is a human follow-up (loop scope ends at
the recipe + artifacts). Note `highest_individual_mae` blend (16.312)
point-beats sim by 0.18 with the CI straddling — at n=261 (one row per
match) the test is underpowered; the val fit (n=545) showed the same
direction.

## What I'd try next

B11 (appended): the val->test alpha shrink is systematic and its
mechanism is known (v1 calibrator E5-fit on the same val balls). A
bias-free val construction — split val, refit a calibrator on half A,
fit alpha on half B — should transfer better; gate it paired vs B3's
blend, not just vs the parents. Also worth an interactive note: E2's
`batter_fours_mae` has no fair baseline in `prop_fair_baselines.py`
(loop-forbidden file); adding one would bring a sixth family into the
blend.
