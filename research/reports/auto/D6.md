# D6 — Retrain the ball model WITHOUT balanced class weights (structural E5 alternative)

**Verdict: CRASH** (2026-07-31). Training is not executable on the frame the
production ball model lives on; no gate number was ever produced.

## Hypothesis

E5's root cause was `balanced` class weights sampled raw (P(wicket) 2.1×
actual, runs/ball +0.38 teacher-forced). Every fix since is post-hoc marginal
patching (E5 v1 vector → A8 → A14/A15 → A16 → B7 → B8, chain closed), which is
phase-uniform and costs `batter_runs_mae`. The untried structural alternative:
retrain with sample weights OFF so the booster estimates P(outcome|state)
directly — balanced weights only help ranking, which a generative sim doesn't
need.

## What happened

Implementation completed cleanly (commit `5fb16bb`, pre-committed before any
eval): opt-in `--no-class-weights` + `--model-dir` trainer flags
(default-preserving), `scripts/auto/d6_marginal_audit.py` (teacher-forced
marginal audit with frozen tolerances |ΔP(wkt)| ≤ 0.005, |Δruns/ball| ≤ 0.05),
and `scripts/auto/d6_gate_analysis.py` (pooled tail-dBrier primary vs the B12
canonical s44 baseline).

The training run died in 1 second (`rc=1`, 2026-07-31T20:18:19Z→20Z):
`assert_venue_alias_contract` (`scripts/identity_maps.py:159`, called from
`scripts/xgboost_v2.py:70`) rejects `data/xgb_data_v3` — its `.feature_hash`
predates I7 and carries no `venue_alias_*` fields
(`venue_alias_version None` vs expected `venue_aliases_v1`, active map sha
`853b32b0…`, 94 active renames). Executor diagnosis (verified): the legacy
ball parquet holds **467** raw venue strings which the active identity map
collapses to **373** canonical venues (92 fold groups);
`models/xgb_v3/venue_encoder_v3.pkl` is 467-class. So the deployed ball model,
the B12 canonical baseline detail, and the entire current prop-sim eval path
live on a **legacy venue-identity contract that the trainer can no longer be
pointed at** — the exact position `CLAUDE.md` documents for the pre-I7 match
model ("new training on the pre-I7 legacy frame is deliberately impossible").

## Orchestrator ruling

Two unblock paths existed; both were declined, and no replacement executor was
launched because neither finishes *this* idea:

1. **Bypass the fail-close** (the trainer is loop-editable, so mechanically
   trivial). Declined on policy: the I7 contract guard is a deliberate
   fail-close encoding a human migration decision; the loop does not engineer
   around fail-closed identity contracts even through editable files. Spirit
   of DO-NOT-CHEAT over letter.
2. **Substitute `data/xgb_data_i7`.** Declined as a confound: it changes the
   training frame (467→373 venues), the stats version, and the pre-committed
   banner/baseline contract simultaneously — a four-way change, not a
   class-weights test. The executor independently refused this too.

Implementation reverted at `2a815e2` (scripts tree byte-identical to claim
`a2188b0`; harness recoverable at `5fb16bb`). `models/xgb_v3/` md5-verified
untouched before/after. Total compute ≈ 4 minutes.

## Side finding (read-only, prod-reference audit; orchestrator-verified vs raw JSON)

The audit tooling was run once against production as a reference
(n = 186,667 test balls, `research/handoff/D6/raw/marginal_audit_prod_reference.json.txt`):

| arm | ΔP(wicket) | Δruns/ball | test mLL |
|---|---:|---:|---:|
| raw, venue_zero (E5's fit distribution) | +0.06470 | +0.38288 | 1.6076 |
| raw, venue_on | +0.07700 | +0.43781 | 1.6297 |
| v1 vector, venue_zero | −0.00160 | +0.02370 | 1.5197 |
| **v1 vector, venue_on (the served path since B6)** | **+0.00576** | **+0.08137** | 1.5090 |

The venue_zero rows reproduce `reports/e5_class_weight_fix.md` exactly
(+0.065/+0.383/1.608 raw; −0.002/+0.024/1.520 calibrated) — tooling validated.
But on the venue-ON path the sim has actually served since B6, the deployed v1
calibrator misses D6's own tolerance on **both** axes: ~19% of the raw
runs/ball overshoot survives, vs ~6% in the distribution it was fit under.

**Not queued as an idea**: B7 already refit the global vector on venue-ON val
predictions and the refit degraded tail props CI-clean (pooled +0.0079) — the
standing B7/B8 lesson is that teacher-forced marginal mismatch does not
translate into prop gains at the aggregate level. This table sharpens *why*
the marginal-calibration chain is closed; it does not reopen it.

## What I'd try next

D16 (queued): the paired twin design on the i7 frame — control (weights ON +
freshly val-fit vector, i.e. the E5 recipe reproduced on i7) vs no-weights-raw,
twin fresh evals at one seed, gates as D6's. Feasibility-gated: it requires an
end-to-end i7 ball-eval path (stats cache/state for `prop_backtest`); if that
doesn't exist, the idea stops at the feasibility check and goes to the
interactive backlog rather than building infrastructure overnight. The frame
(`data/xgb_data_i7`) and an i7 ball model (`models/xgb_i7`, 373-venue encoder)
already exist. Alternatively the humans may choose to sanction a one-off
legacy-contract training exception for research sidecars — that is their call,
not the loop's.
