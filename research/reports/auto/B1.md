# B1 — Fix sim venue blindness (`venue_encoded=0` on every sim ball)

**Verdict: TABLED** (sim gate pair: GATE 1 primary not met, GATE 2 guards held —

## Hypothesis

`xgboost_v2.py` fits a venue LabelEncoder at training time but never saves it,
and `sim_v1_2.py`'s `XGBoostModelV2._feat_buf` defaults missing keys to 0 — so
every simulated ball scores as venue code 0 while training saw real codes
(TODO.md "Pipeline bugs", filed at E5). The sim literally cannot see the venue:
an out-of-distribution input on every ball. Restoring the training-time codes
should improve venue-sensitive props (totals, boundaries) across the board.

## What I did (implementation by the 2026-07-11 iteration; eval + verdict here)

- `scripts/auto/b1_build_venue_encoder.py`: rebuilt the training-time venue
  LabelEncoder from `data/xgb_data_v3` (LabelEncoder sorts classes, so a refit
  on the same parquet is deterministic). **Training-exactness proven** by
  refitting the batter and bowler encoders the same way and byte-matching them
  against the artifacts saved at training time (6932/5179 classes MATCH; the
  script ABORTS on drift). 467 venue classes; **261/261 polymarket_test venues
  covered**.
- `XGBoostModelV2`: new `venue_encoder_path` param (mirrors LSTM/Transformer
  wrappers) + auto-detect of a `venue_encoder_v3.pkl` sidecar next to the
  model. `extract_features` sets `venue_encoded` via cached dict lookup, −1
  for unseen venues (batter/bowler unknown convention). No encoder present →
  key unset → buffer default 0 == legacy behavior; `models/xgb_v3/` untouched,
  so the **default sim path was byte-unchanged** even before the revert.
- Smoke (5 test matches, paired feature extraction legacy-vs-fixed): only
  `venue_encoded` differs; fixed codes == training encoder codes.
- Eval (this iteration; the prior one was killed at startup by the wall
  clock): recipe B, `prop_backtest.py --test-dir data/polymarket_test
  --n-matches all --n-sims 100 --seed 42 --ball-calibrator vector
  --model-path models/auto/b1/xgboost_model_v3.pkl` (symlink + sidecars;
  startup log confirms "venue encoder ACTIVE (467 venues)") →
  `models/auto/b1/detail_venue_n261.json`, 2198.6 s. Paired vs the SAME
  venue-blind single-vector baseline every A-series sim idea used,
  `models/auto/a8/detail_vec_n261.json` (cluster-bootstrap by match), via
  `scripts/auto/b1_gate_analysis.py`.

## Verdict

**TABLED.** GATE 1 not met + GATE 2 held = exactly one gate satisfied, which
the pre-committed mapping in `b1_gate_analysis.py` (committed at `230427a`,
before any eval numbers existed) maps to TABLED. Implementation reverted
(`c37f1b0`); gate script, report, and scratch (`models/auto/b1/`:
`venue_encoder_v3.pkl`, `detail_venue_n261.json`, `gate_analysis_output.txt`,
gitignored) kept. The default sim path was byte-unchanged by the
implementation anyway (encoder only activated via the `models/auto/b1/`
sidecar), so the revert changes no production behavior.

Honest reading: the fix is directionally real but the pre-committed primary
targeted the wrong families. Venue identity helps the sim most at the
**batter level** — `batter_runs_mae` −0.175 [−0.298,−0.048] is a CI-clean
improvement on E2's single validated sim skill (continuous score forecasts),
and the batter-fours/50plus binaries move with it — while the team-total
binary lines the gate pooled (innings_runs especially) are flat. Mechanism
guess: venue codes sharpen per-batter outcome distributions (the model can
finally use venue-conditioned interactions with batter features), whereas
team-total lines aggregate 120+ balls and two teams, washing the per-ball
correction out the same way A8/A12/A16 saw aggregate washout.
